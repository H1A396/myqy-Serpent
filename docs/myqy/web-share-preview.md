# 网页分享：主线页面与开发测试页面

> 本文件规定网页分享（web share）界面的改动流程。与 git 的主线/开发分支模型一致：
> **主线页面只接受已验收的改动，一切尝试都在开发测试页面进行。**
> AI agent 在改动 `src/myqy-web-share/client/` 下任何文件前，必须先读本文件。

最后更新：2026-09-30

## 1. 两个页面（固定，不得混淆）

| 页面 | 地址 | 角色 | 语义 |
| --- | --- | --- | --- |
| **主线页面** | `http://127.0.0.1:47890/` | 正式版 | 等价于 git 主线分支，**只呈现已验收的构建** |
| **开发测试页面** | `http://127.0.0.1:47890/web-preview/` | 测试版 | 等价于测试开发分支，**所有试验都在这里发生** |

两者的物理来源：

- 主线页面 ← `dist/web/`（静态根目录本身）
- 开发测试页面 ← `dist/web/web-preview/`（静态根目录的子目录）

预览目录**必须**位于 `dist/web/` 之内。分享服务的静态根是 `dist/web`，服务端会把每个请求
路径解析到该根之下并拒绝根外的路径；放在根外的目录无法被访问。
（2026-09-30 实测教训：放在 `dist/web-preview` 时服务端取不到文件，且会因 SPA 回退
错误地返回 `dist/web/index.html`，表现为 `/web-preview/assets/*.css` 返回 HTML。）

## 2. 改动流程（强制）

1. **不要在主线页面上直接试验**。任何网页分享界面的调整都在开发测试页面观察。
2. 改 `src/myqy-web-share/client/` 下的源码。
3. 构建开发测试页面：

   ```bash
   npm run web:build:preview
   ```

4. 刷新 `http://127.0.0.1:47890/web-preview/` 查看效果；对比时可同时打开主线页面。
5. 效果确认、用户认可后，**才**把改动应用到主线页面：

   ```bash
   npm run web:build
   ```

   注意：主线页面的更新是一次显式动作，不应在每次启动开发时被自动触发。

## 3. 不得让主线页面被自动覆盖

- **`npm start` 不得自动重建 `dist/web`**（`prestart` 中已移除 `build-web.mjs`）。
  否则每次启动都会用当前未验收的源码覆盖主线页面——2026-09-30 已发生过一次。
- 若需要恢复自动化，必须先确认主线页面不会被未验收改动污染，并更新本文件。
- `npm run package` / `npm run web:build` 产出的是主线页面（`dist/web`），用于发布。
- `dist/` 已被 `.gitignore` 忽略，两个页面都不进版本控制。

## 4. 边界

- 本规则只针对**网页分享客户端**（`src/myqy-web-share/client/`、`vite.web.config.ts`）。
- 它与 Electron 桌面客户端（`src/renderer/`）是两套独立构建，改动不得互相牵连。
- 修改 `package.json` 的 `prestart` 等会同时影响桌面开发流程的脚本时，必须单独说明影响面。
