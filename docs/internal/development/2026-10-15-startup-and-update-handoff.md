# 2026-10-15 登录启动与更新交接

## 登录时启动

设置 → 常规提供「登录时启动」。偏好保存在应用数据的 `startup-preferences.json`。已安装的 macOS 与 Windows 应用在用户修改时调用 Electron `app.setLoginItemSettings`。登录时启动保持打开时，下次启动会再次注册。默认关闭时不在每次启动时改写系统登录项。开发态和自动化会话不注册，避免把开发用的 Electron 可执行文件写成登录项。Linux 没有对应 API，界面说明当前系统不提供这项。

Windows 注册时始终传入空参数列表，清掉先前可能写入登录项的启动参数。系统若返回 `requires-approval`，设置页提示到系统设置的登录项中启用。

先前误加的「静默启动」已移除。它不是产品需求。更新期间反复弹出窗口由下面的交接处理，不通过隐藏登录窗口解决。旧偏好文件里若仍有 `silentLaunch` 字段，读取时忽略，不影响「登录时启动」。

## 更新后的窗口循环

0.2.9 到 0.2.10 的主进程差异里没有新增的循环启动器。更新交接本身有两处会在安装期间反复出现窗口：

1. 安装器已经交给系统之后，收尾仍删除下载的 macOS 磁盘镜像，或删除刚启动的 Windows 安装程序。磁盘镜像被删会让系统反复尝试打开；Windows 安装程序被删会启动失败并再次弹出。
2. 退出要等 Worker 结束，这段时间单实例锁还在。安装器或系统再次启动应用时，第二实例进不来，原进程的 `second-instance` / macOS `activate` 会把主窗口重新显示。安装器看到进程仍在，就继续关闭并再次启动。扩展服务和 MCP 服务也要等这次退出才释放本机回环端口。

处理：

- 安装器成功打开后保留磁盘镜像；Windows 仍删除压缩包，但保留解压出的安装程序，由原有的延后清理在安装程序结束后删除。打开失败时仍然删除。
- 交接开始后隐藏已有窗口。macOS 同时隐藏应用。退出标记一旦置上，第二实例、程序坞激活、聚焦请求，以及交接之后新建的窗口，都不会再把界面显示出来。
- 立刻关闭本机回环服务。更新交接若在 8 秒内还没退出，强制结束进程，避免单实例锁和本机回环端口一直留下。日常退出仍先等 Worker 结束。

未在本机用 0.2.9 安装包走到 0.2.10 的真实更新。验收项为 `STARTUP-LOGIN-001` 与 `UPDATE-HANDOFF-001`。
