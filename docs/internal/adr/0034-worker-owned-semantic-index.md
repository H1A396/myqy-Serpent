# ADR-0034：Worker 管理资源库内的正式语义索引

- 状态：2026-10-13 用户授权，设计采用；实现、性能与平台验收进行中。
- 替代 ADR-0011 关于 MVP 不生成或存储向量的决定。
- 工单：Serpent-424d7b。

## 背景

dev 已提供语义搜索与找相似，但 Main 的 JSON 缓存逐条重写全部向量，并在内存遍历排名。用户要求正式持久化，且希望一万资产的搜索首屏在 500ms 内完成，由 Luna 开发、主 agent 设计和监督审查。

## 决策

使用资源库内 `.serpent/semantic/index.sqlite`，由 Library Worker 独占管理。普通表保存明确小端 Float32 BLOB、profile、source revision、可恢复任务及迁移记录；sqlite-vec 稳定版提供精确 cosine 距离计算，扩展不可用时保持有界的正确性降级。核心 library.db 仍是资产事实源。

Main 继续管理模型推理与凭据，通过内部校验命令接收 Worker 准备的有界媒体或文本输入；不持有整库向量 Map，不读取资产路径或打开数据库。Worker 写前和读时核验当前资产版本与库身份。两库独立事务，通过幂等任务和重启对账收敛，不宣称跨库原子性。

复用现有筛选、范围和渐进浏览；在排名截断前筛选候选，保持原始 cosine 分数与稳定并列顺序。查询取消与索引任务代次分别管理。旧 JSON 后台有界迁移，验证完整关闭重开后才清除属于本应用的旧缓存。

沿用本地 WAL、网络或未知盘 DELETE/FULL 策略。原生扩展只从受控应用资源加载；索引损坏不能阻断普通库功能。选择独立库是为隔离派生数据体积、迁移与损坏，不将 ANN 或额外服务进程引入本轮必要范围。

## 后果与验收

跨设备 profile 匹配、资源库复制与导出、native 打包和异常清理需要显式实现与证据。相同远端模型名不保证权重不变，不能声称自动发现服务端模型替换。

一万资产 500ms 作为优化与实测目标，默认包含查询向量生成至首屏；分别报告各阶段与总耗时，缓存或预生成向量排名不代表端到端通过。保留两万媒体资产基线。完整资源库可用性、真实 Electron 核心旅程、最终主线门禁由主 agent 串行执行；没有 Windows 或当前 packaged 证据时记录未验证。
