# 通用 Embedding 接入与资产找相似

日期：2026-10-11。状态：找相似一期已通过人类验收。自定义文本服务已接到设置、探测和文本索引；Worker 向量库和云端图片、音频、视频仍未实现。方案工单：`Serpent-rrun4`；找相似 P1 功能工单：`Serpent-7skmn`。

本文细化 [EmbeddingGemma 2 接入方案](../research/2026-10-10-embeddinggemma-2-integration-plan.md) 的通用模型部分，并增加找相似。此前权重组合、模态验证和重建纪律继续有效；本文规定通用配置、调用契约与交互边界。实际现状是三档 Gemma 测试接入、Main 持有实验索引和全局模型偏好；它们不等同于本文的生产能力。

## 产品决定

1. 全局设置管理模型、连接、能力验证和默认模型；资源库设置决定该库使用哪个模型及哪些模态。修改全局默认值只影响首次启用语义搜索且尚未绑定模型的库，不隐式重建已有库。
2. 模型生成向量，本地索引保存向量并完成检索。云端生成向量不要求上传整个向量数据库，但需上传要编码的内容和搜索文字。
3. 按协议实现适配器，按模型登记配置。支持任意符合已支持协议、通过验证的模型；不能承诺任意模型 URL 或任意 GGUF 无需适配即可使用。
4. 首期保留 Gemma 三档预设，支持自定义本地服务与云端服务；本地 GGUF 托管运行时只支持已验证的架构。自定义 ONNX、Transformers 或其他格式可由用户先部署为兼容服务；应用不执行配置里的任意脚本。
5. 语义结果按相关性顺序，默认每批 50 条，复用现有 25/50/100 设置。批次数量控制展示，不保证每条结果相关；本期不增加未经标注校准的相似度门槛。
6. 更换模型重建的是语义索引，不删除或替换资源库数据库，也不改变原文件、标签、描述。旧索引在新索引成功发布前继续使用。
7. 语义搜索开启后，单个资产右键可“找相似”。第一阶段支持已验证的图片向量；其他模态随各通道能力验证逐步开放。

## 配置和身份

| 对象 | 所属位置 | 内容与约束 |
| --- | --- | --- |
| ProviderConnection | 设备设置 | 稳定连接 ID、名称、适配器 ID、端点、credentialRef、超时/并发配置；区分本机服务、局域网和互联网目的地 |
| ModelDefinition | 设备模型注册表 | 稳定模型 ID、provider ID、服务模型名或权重清单、声明能力与验证结果；不是固定三项枚举 |
| EmbeddingProfile | 不可变版本 | 模型 revision、权重/投影校验值、编码角色参数、维度、度量、归一化、预处理、分段/聚合、兼容空间和适配器语义版本 |
| LibraryEmbeddingBinding | 资源库配置 | enabled、activeProfile、activeGeneration、请求的目标 profile 与 pending generation、模态策略 |
| VectorRecord | Worker 派生存储 | assetId、revision、profileKey、channel、segment/time range、向量；不能仅以资产 ID 区分缓存 |
| SearchSession | Worker 临时查询状态 | 库、generation、查询类型、过滤快照、有序结果、游标、过期时间；不持久化原始用户查询 |

profileKey 是规范化配置的哈希，不包含设备路径、API Key 或界面名称。更改输出维度、查询前缀、权重、pooling 或图片预处理均产生新 profile。修改显示名称、批次数量、并发、凭据轮换不自动重建。更换服务端点默认要求重新验证并视为新目标；只有可证明同一固定模型及编码配置时才可保留原 profile。远端服务仅提供可移动别名时，显示“版本未固定”，记录用户声明版本和验证指纹，定期合成 canary 检测漂移；这不能证明服务没有变化，检测到变化暂停增量写入并要求重建。

维数相同不等于向量空间兼容。同一模型的 query/document 角色可以参数不同，但必须是模型规定的成对检索模式。asset-to-asset 必须另有明确的兼容声明与测试；不能假定非对称文本模型的 document 向量适合互相检索。

可搬运的资源库保存脱敏 profile 身份和能力说明，不保存设备模型路径、端点凭据或密钥。换设备后按 profile 重新映射本机连接；无法映射时关键词搜索仍可用。已缓存的兼容资产向量可继续找相似；文本搜索生成新查询向量需连接可用。

## 适配器契约

在现有 `src/shared/embedding/profile.ts` 上拆出通用 Zod schema；保留 Gemma 常量作为预设。编码职责从 `EmbeddingTestIndex` 提取为 provider 服务，避免 Main 继续充当资产文件和索引所有者。

适配器最小接口：`probe(connection, definition)`、`encode(profile, role, inputs, signal)`、`dispose()`；托管本地运行时另提供 `prepare/start/stop`。role 为 `query`、`document`、`similarity`，由 profile 决定真实请求参数；输入为带稳定 item ID 的文本、图片或媒体片段，输出按 item ID 对应向量、usage 与结构化错误。批量响应按服务 index 验证映射，禁止依赖响应顺序盲配资产。

首批协议：

| 适配器 | 支持范围 | 配置方式 |
| --- | --- | --- |
| 托管 llama.cpp 多模态 | 已验证 GGUF 架构与运行时组合 | 复用已有会话、模型安装和权重目录管理；Gemma 三档是预设 |
| 通用 embeddings HTTP | 标准文本 embeddings 请求/响应 | URL、模型名、认证引用、允许的维度参数与角色模板；支持本地和远端 |
| llama.cpp 多模态 HTTP | 显式的嵌套 content 输入扩展 | 独立协议选项，按模态 probe，不因端点名相同自动启用 |
| 云端原生多模态 | 经验证的 provider 独立请求合同 | 在后续阶段增加至少一个真实 provider；按实际模态和限额开放 |

“兼容 embeddings API”不意味着支持图片。llama.cpp 的多模态 content 输入是扩展；其官方说明明确区分标准协议与多模态对象。自定义 JSON 模板、脚本请求转换和任意 header 表达式不放入首期 UI；不兼容服务通过受控适配器/后续 provider 扩展支持。

设置探测包括：连接/认证、实际编码、维度/有限数/非零范数、批量 item 对应、两种不同合成内容输出确实不同、已知合成配对的跨模态检索、query/document 角色一致性、相同输入重复输出容差。图片 probe 使用内容不同的合成图，防止服务静默忽略图片。它证明合同有效，不宣称真实检索质量合格。文本、图片、音频、视频各有 `unsupported/declared/verified/failed` 状态；每次配置语义变化使对应验证失效。

只按模型推荐度量检索：cosine 时索引和查询均 L2 归一化，再以内积计算；dot 和 L2 保留其定义，不统一强制归一化。结果分数用于内部排名，不展示成“匹配百分比”。不同空间/通道的原始分数不能直接拼接排序。

错误包括认证、网络、超时、限流、模型不存在、输入不支持、配额、响应格式和非法向量。失败不是成功且零结果；用户可重试，已有结果保留。只对允许重试的错误指数退避并尊重 Retry-After，限制并发、总重试和费用预算；取消要传递到运行时/网络及任务持久状态。

## 设置与资源库交互

复用 `AppSettingsDialog`、`SemanticSearchSettings`、`SettingsCard`、`DialogShell` 和主题 token。模型页展示来源、已验证模态、是否默认、就绪/未连接状态，以及添加、编辑、测试、设为默认、删除。已有三档注册表升级为通用模型列表。凭据复用 Main 的 safeStorage 管理方式，Renderer 不读回密钥；资源库不保存密钥。本机服务可以无认证，局域网服务也属于内容离开设备的连接，不能标为“完全本地”。远端使用 HTTPS；非加密局域网连接须明确告知传输方式。

资源库设置显示当前模型、已启用模态、索引覆盖率及重建任务；选择列表来自模型注册表且只允许已验证的所需能力。首次默认值仅预选，启用云服务仍需本库确认上传范围。绑定模型的配置编辑不能就地改变 active profile：保存为新版本，在受影响库显示可切换项；删除被使用的模型先列出受影响库，不能静默解绑。

模态开关区分原生和兼容：

- 文本：支持的文本资产，按固定提取/分段策略；图片文件名/标签不默认混入视觉向量。
- 图片：真正图片编码。只有文本能力的模型不能伪装成图片能力；如未来提供生成描述后编码，必须作为独立且明确标注的策略。
- 视频原生：只有 probe 与目标运行时真实验证后开放。
- 视频抽帧：图像能力足够时可选，标注“通过抽帧分析画面，可能遗漏短暂内容”；默认均匀覆盖且最多 32 帧，策略随 profile 固定。音轨单独选择，不声称抽帧支持声音。
- 音频：原生音频能力通过后开放；语音转文字是独立可选兼容流程，标注只分析转写内容，不能代表声音/音乐相似。

云端确认列出上传目的地、内容类型、当前资产/片段估算、费用或“暂无法估算”，允许授权同一库同一目的地和模态的增量编码。增加模态、更换目的地、扩大上传范围重新确认。query 文本也会发送到该连接，应在初次确认说明；已缓存向量的找相似不发新媒体请求。远端重定向不能把凭据和媒体转给未经授权的目的地。

切换弹窗：“更换语义搜索模型？”“将为此资源库重新建立语义索引，可能需要一段时间。原文件、标签和描述不会改变。完成前将继续使用原模型。”首建或旧模型不可用时改为仍可关键词搜索。复用后台任务进度条：准备、扫描、编码、追平、发布；未知总量使用不定进度，失败/跳过单独显示；支持暂停、继续、取消、重试。

## 索引与检索边界

Library Worker 唯一拥有资产读取、SQLite 与派生索引；Main 管理连接/凭据和运行时生命周期，可启动隔离 encoder helper。Worker 读取并预处理媒体，通过受限编码 RPC 交付内容，Main 不扫描资源库和打开数据库。Renderer 只传库/资产 ID 与配置，所有命令响应/事件经 Zod 验证。

生产索引从 Main 整库 JSON 改为 Worker 的增量派生存储。首期选用库内独立派生 SQLite，向量以定长 Float32 BLOB 存储，按有限批量事务写入。绑定和任务检查点沿用库级持久任务机制；主库新增结构只做追加迁移，派生库丢失可重建。内存按通道保持连续向量块，查询在 Worker 进行精确扫描，避免每张图片全量 JSON 重写和 Main 同步 I/O。20,000 × 768 × 4 字节约 61.44 MB/单通道，仅向量数据，不含片段、元信息和临时代次；切换预检旧+新代次、媒体中间产物和安全余量。不得声称多模态全部仍只有这个大小。

先基于项目 20,000 资产基线测首屏、冷加载、增量写入、取消延迟和 UI 响应，再决定是否引入 ANN。精确检索提供完整可排序的命中集合，按分数降序、assetId 稳定打破同分。后续 ANN 需要独立召回率证据与候选扩展策略，不能把反复增大 TopK 当作稳定分页。

正式协议建议 `semanticSearch.start({libraryId, query: text | asset, scope, filters, pageSize})` 返回 sessionId、generation、首批、nextCursor；`page/close` 分页和释放。Worker 保存有序 ID/分数快照，Renderer 仅逐批获取摘要。游标绑定 session 和已消费排名，不依赖当前摘要数量；失效/删除项不会重复拉取空页。默认当前资源库全库搜索，不联合其他库；显式筛选可缩小范围并创建新会话。相关性模式不应用修改时间或手工排序覆盖名次。

已显示前缀不因新增资产或后台索引更新重新排序；查询时冻结 active generation，新增内容由刷新/新查询纳入。旧代次有读者时保留引用，过期或切库释放会话；无法保留旧代次时明确会话过期而不是把新代次结果混入。修改筛选/更换查询/关闭语义模式递增请求代次并取消旧请求，迟到响应不得覆盖新视图。删除资产可移除其卡片且游标保持原排名推进。

重建遵循旧方案的快照+durable delta 追平，发布事务再次核对高水位；失败/取消保留旧 active，重启从检查点恢复。用户选择接受部分索引时明确覆盖率和失败列表。清理只删本任务拥有的临时文件和无引用旧代次，不删除共享模型；失败须可见并可重试。当前实验 JSON 不直接当作生产索引导入：具备完整可验证 profile/revision 才可迁移，否则重建。

## 资产右键“找相似”

一期为单图片查询，不是重复文件检测，不依赖文件名、OCR 或标签匹配。复用资产右键菜单 descriptor/controller，不给巨型 `App.tsx` 增加完整状态机。

| 状态 | 菜单行为 |
| --- | --- |
| 语义搜索关闭 | 不显示“找相似” |
| 单资产、受支持模态 | 显示“找相似”；已有向量时立即查询 |
| 模态不支持/未验证 | 禁用，标准 hover 提示“当前模型不支持此类资产” |
| 支持但向量待生成 | 点击后进入准备状态，提升该资产任务优先级，完成后查询 |
| 编码失败/内容不可读取 | 显示可操作原因和重试，不显示空成功 |
| 多选或回收站 | 首期不显示；不偷偷使用第一项 |

源资产来自当前库已发布 active generation，按 assetId+revision+profile 查缓存。若 revision 已变则重新编码后创建新查询；无有效 active 时说明索引准备中。pending 重建期间仍用旧 active，不混用新模型的源向量。已缓存且 profile 支持对称相似检索时本地完成；若模型需要 similarity 角色单独编码，则按该 profile 生成并缓存 similarity query 向量，云请求仍必须在已有授权内。

检索排除源 assetId 和回收站资产，其他相似副本保留。排名按 profile 的同空间度量，稳定同分，不能人为将相同名字置顶。图片一期只搜视觉空间兼容的图片；后续可搜视频视觉通道。音频查音频，视频按版本化聚合查询并可用片段定位；跨通道仅在能力验证声明共同空间或以显式排名融合时开放。

结果复用当前搜索画布和分页：顶部显示源资产小缩略图与“与此资产相似”，可取消返回原浏览位置。查询源不是普通文本字符串，不覆盖用户原有搜索草稿；结果卡片仍支持查看、选择和右键，可对结果再次找相似。导航返回恢复来源 scope、筛选、选中项和滚动锚点，历史项用资产 ID 而非文件名。首期沿用当前筛选条件且界面保留可见筛选条；点击清除筛选创建新会话。更换排序不会悄悄打乱语义排名，应禁用普通排序控件并显示“相关性”。

每次滚动追加只能扩展同一快照后缀。旧卡片的 ID、相对次序和滚动锚点不变；图片解码和瀑布流几何变化复用既有锚点机制。源资产删除/变更时当前结果标注来源不可用或可刷新，不静默换源；切库、关闭搜索或新查询取消排队编码及查询订阅，但不取消其他资产共享的后台索引任务。

## 实施顺序与验收

先修分页实际画布重排缺陷，建立真实多批次回归；其后功能可分开交付，找相似一期不被全部云端支持阻塞。

1. 当前 Gemma 图片找相似：只增加源资产向量查询合同、独立 controller、菜单与结果来源态，复用稳定分页；不新增重排算法。已接到现有实验索引，见 `EMBED-SIMILAR-001`。
2. 通用配置与本地/云端文本服务：通用 schema、协议 adapter、probe、凭据与注册表；保留 Gemma 图片 adapter；文本模型不得开放图片菜单。见 `EMBED-SERVICE-001`。文本索引仍在实验 JSON 缓存，不是 Worker 派生库。
3. Worker 派生存储、库绑定和可恢复重建：迁移实验索引所有权，替换全局实际模型选项；默认设置只初始化新绑定。
4. 经验证的云端多模态和音频/视频策略：逐模态上线；补片段索引、预算、跨通道匹配与找相似扩展。

| --- | --- | --- | --- |
| 通用模型配置 | shared/embedding 通用 schema、Main provider registry、设置页 | 同协议多个模型无需改枚举；凭据不回传；错误/取消/响应映射 | 本地与远端真实服务逐项操作；尚未执行 |

| 默认与库绑定 | Library Worker binding、资源库设置 | 两库不同模型；全局默认不改旧库；迁移不丢用户数据 | 双库切换和完整退出重启；尚未执行 |
