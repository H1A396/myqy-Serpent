# 0.3.0 文档审计

对照草稿发布说明、`v0.2.10` 之后的用户向行为，以及 `docs/`、`README`、发布流程中的现有文字。行为以设置文案和当前实现为准。版本名使用 **0.3.0**。

## 缺口

| 主题 | 审计前 | 处理 |
| --- | --- | --- |
| 全新 UI | 使用手册没有「新 UI / 旧 UI」开关、自定义主题、背景与面板不透明度。术语表和产品简报仍把自定义主题写成推迟。插件手册只列出四套旧 profile 名。 | 写入使用手册「外观：全新 UI」。术语表增加「全新 UI」。产品简报注明 0.3.0 已提供。插件手册改为「内置主题 + 自建主题 + 布局开关」，插件仍只读语义 token。 |
| 语义搜索（实验性） | 使用手册没有入口、本机模型、自定义服务、按库开关和索引位置。术语表「向量搜索」仍写「不进入 MVP」。产品简报仍写不提供向量搜索。 | 写入「搜索与过滤」。术语表增加「语义搜索」，并把「向量搜索」指到该项。产品简报保留 MVP 原句，并注明 0.3.0 的实验性能力。 |
| Linux x64 AppImage | 安装手册已写获取、`chmod +x`、FUSE 和内置媒体工具，但仍有「bundle 未晋升」的用户向句子。故障排查、两份 README、开发环境、贡献说明、发布流程和 `local-cicd.md` 仍写「依赖系统 ffmpeg / 无 pinned bundle」。`bundle-lock.json` 中 `linux-x64` 为 `ready`。 | 用户向说明改为：发布包内置 `ffmpeg` / `ffprobe` / `oiiotool`，减少对 PATH 的依赖；环境变量仍可覆盖。开发态 `npm start` 在未执行 `media:ensure` 时仍用系统 PATH。linux-arm64 仍无该包。 |
| 文件夹封面 | 使用手册只写了图标与颜色，没有从资源库、从文件、从资产菜单设置封面，也没有恢复默认。 | 写入「文件夹封面」。 |
| 登录时启动 | 使用手册没有这项。 | 写入「设置 → 常规」：已安装的 macOS / Windows 写入登录项；批准与注册失败的提示；Linux 显示不提供且没有开关；未打包的开发运行只记偏好。 |
| 卡片文字对齐 | 使用手册没有左/中/右，也没有工具栏循环。 | 写入浏览一节。 |
| 发布说明规则 | `release-process-and-distribution.md` §5 已有「未对用户发布过的中间改动不进 Release Note」（2026-10-15）。检查清单只覆盖「用户能直接感知」，没有把这条收成勾选项。 | 清单增加对照上一正式 Release 的勾选项。规则正文补充：未发布的过渡版本号（草稿中的 0.2.11）不是对照基准；退出时回收本机语义模型进程不单列；内部称呼并入「全新 UI」。 |

## 有意不写进用户手册

- 退出时拆掉本机语义模型进程：开发周期内的修复，用户没有可对照的界面。
- 「静默启动」以及发布前撤回的中间形态。
- 视频封面取 25% 时间点：若已在 v0.2.10 交付，不作为 0.3.0 新能力重写。
- 内部代号「浮岛」，以及把阴影、圆角单独写成一项功能。外观页上的字号、层级投影、圆角只作为全新 UI 的外观控件带过。
- 设置安装列表里未出现的「标准 / 较高」模型档。界面字符串还在，设置列表目前只有 EmbeddingGemma2（紧凑档）。见下方待确认。
- 未改 `package.json` 版本，也未新增仓库内的 GitHub Release 正文。

## 待产品负责人确认

1. 语义搜索设置目前只安装 EmbeddingGemma2 紧凑档（`SETTINGS_LOCAL_SEMANTIC_MODELS`）。「标准」「较高」的文案和体积数据仍在代码里，安装卡片标题也固定用紧凑档文案。文档按当前设置页书写。若 0.3.0 要开放另外两档，需要改设置列表后再改手册。
2. 层级投影、圆角、菜单模糊的控件在外观页上始终可见。文档把它们算作全新 UI 的外观控件，没有逐项写成独立功能，也没有声称旧版布局完全没有这些控件。
3. 产品简报仍是 MVP 边界记录，只在开头和相关句子标明 0.3.0 已超出的部分。
4. 本机模型「找相似」按 `LOCAL_GEMMA_INPUT_MODALITIES` 写成图片、视频、音频、文本。自定义服务仍按设置文案写成：文字搜索可用，按图片找相似用本机模型。
